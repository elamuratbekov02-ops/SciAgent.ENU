# SciAgent.ENU

Smart.ENU «Научная деятельность» бөліміне арналған ЖИ-агент, ҒЗЖ есебін құрастырғыш және ғылыми аналитика. Бұл «ЖИ-әзірлемелер» байқауына арналған MVP, мысал ретінде Менеджмент кафедрасы алынған. Интерфейс әзірге орыс тілінде.

Модуль «Профиль ученых» мен «Научные работы» тармақтарының жанындағы үшінші тармақ: «Научная отчётность». Барлық функция осының ішінде, ал бүйір мәзір, жоғарғы жолақ және лауазым ауыстыру Smart.ENU-дағыдай. Модульден тыс мәзір тармақтары басылмайды.

**Бұл ресми Smart.ENU жүйесі емес.** Беттің өзінде бұл жазылмайды, сондықтан сілтемені беріп тұрғанда өтінімде және қорғауда айтылуы керек. Модуль логин сұрамайды және ешқандай ресми жүйеге қосылмайды.

## Мақсаты

Ғылыми нәтижелерді бір рет енгізу арқылы есептілікке кететін қол еңбегін азайту және кафедра, факультет пен университет басшылығына дұрыс, бірыңғай дерек беру.

## Міндеттері

1. Бір деректі қайта енгізу қажеттігін жою.
2. Smart.ENU-дағы жазбаларды, Platonus пен Scopus импортын бір процеске біріктіру.
3. Файл, сілтеме не мәтіннен деректі ЖИ арқылы белгіленген форматқа келтіру.
4. Қайталануды, қатені және бос өрістерді енгізу сәтінде анықтау.
5. Ф ЕНУ 605-02-25 есебін автоматты түрде құру.
6. Әр рөлге өз деңгейіндегі аналитиканы беру, ғылыми жетекшілікті көрсету.
7. Дербес деректі рөлдік қолжетімділікпен және әрекеттер журналымен қорғау.

## Процесс

**Жыл бойы, әр нәтиже:** автор «Мои результаты» бетінде енгізеді (файл, DOI, форма), карточканы тексеріп жібереді. Білім алушының жазбасын ғылыми жетекші, содан кейін кафедра меңгерушісі келіседі. Оқытушының жазбасы бірден меңгерушіге барады, меңгерушінің жазбасы директорға барады. Өз жазбасын ешкім өзі келіспейді, жетекші жауап бермесе меңгеруші оның орнына келісе алады. Есеп пен аналитикаға тек келісілген жазба кіреді.

**Жыл соңында:** Ғылым департаменті науқанды ашып мерзім қояды. Жүйе мерзімге 14, 7, 3, 1 күн қалғанда және сол күні әркімге өз ісін еске салады. Автор өз тізімін растайды, жауапты кафедра тізімін тексеріп есепті жібереді, меңгеруші хаттамамен келіседі, директор қол қояды (нұсқа бекітіледі), Ғылым департаменті қабылдайды.

ЖИ файлды оқып карточка толтырады, чатта жауап береді, аналитикалық анықтаманың жобасын жазады. Crossref пен құжатты салыстыру, бөлімді анықтау, қате мен қайталануды табу, келісушіге алдын ала тексеру ережемен жасалады. Шешімді адам қабылдайды.

## Деректер

- **Нақты:** Менеджмент кафедрасының 2025 жылғы есебіндегі құрылым, сандар, жарияланымдар және жүлдегер білім алушылар. Аттар есепте қалай жазылса, солай сақталған.
- **Ашық дереккөзден:** кафедра оқытушылары мен дәрежелері [портфолио беттерінен](https://fe.enu.kz/ru/portfolio/department/cafedra/18638), жоғары мектеп туралы мәлімет [сайттан](https://fe.enu.kz/ru/page/about-the-faculty) алынды (`data/staff_public.json`).
- **Қосылмаған:** есептегі телефондар мен email-дер. Рөлдік қолжетімділікті көрсету үшін жүлде жолдарында ешкімге жетпейтін сынақ мәні тұр (`+7 000 000 …`, `…@example.edu`).
- **Условные дерек:** басқа кафедралар мен факультеттердің сандары, жоспар мәндері, докторант талаптары, журнал тәуекел тізімі. Осы сандар шыққан жерде бір жолмен жазылған.
- **Мысал жарияланымдар:** табылған жарияланымдар мен сынақ импорты ойдан жасалған, атаулары «[Пример]» деп басталады және тек демо иесіне тіркелген.
- **Үлгі диплом:** `3_diplom.png` ойдан жасалған, ондағы адам (`Ульгиева А.Б.`) да жасанды және кафедра тізімдеріне кірмейді.

Нақты адам туралы жалған мәлімет болмауы үшін демода бірнеше шектеу бар:
- Оқытушыға дәреже, топ не «расталмаған» мәртебесі ойдан тағылмайды.
- Есепте жазбасы жоқ оқытушының аты аналитикада шығарылмайды.
- Докторант тәуекелінде басқа докторанттардың аты жасырылады, өйткені талап мәндері мысал.
- Бірлескен автор түрі есепте жол деңгейінде жоқ, сондықтан сан шығарылмайды, ол агент белгілеген соң есептеледі.
- Басшылық лауазымдары адам атымен емес, рөлімен көрсетіледі, сондықтан демодағы келісу мен қол қою нақты адамның әрекетіндей көрінбейді.

`data/seed.json` файлын `tools/build_seed.py`, бос нысанды `tools/build_template.py` жасайды, ал `tools/check_seed_privacy.py` осы ережелерді тексереді.

Сілтемені интернетке шығарғанда `SCIAGENT_DEMO_PASSWORD` орта айнымалысын қойыңыз: демода логин жоқ, ал ішінде оқытушылар бойынша сандар мен жүлдегер білім алушылардың аты бар.

## Қауіпсіздік

- Модельге пайдаланушы жіберген файл мен мәтін, рөліне сай жазба атаулары, оқытушылар аты және агрегатталған сандар кетеді. Білім алушылардың аты, телефон, email және ЖСН кетпейді. Авторды анықтамалықпен салыстыру серверде жүреді.
- Диаграмма мен файлды модель емес, сервер жасайды, рұқсатты да сервер тексереді.
- Телефон мен email тек есеп дайындайтын жауаптыға және жазба иесіне ашылады, әр ашу журналға жазылады.
- Индекс мәртебесін модель болжамайды: ол базадағы жазбалар мен тізім бойынша тексеріледі.
- Құжат ішіндегі нұсқаулар дерек ретінде ғана қабылданады, жазбаны адам растамайынша сақталмайды.
- Демода логин жоқ, сондықтан сілтемені құпия сөзсіз ашпаңыз. Пайдалануда кіру Smart.ENU арқылы болуы керек.

## Іске қосу

Python 3.11 немесе жаңасы керек.

```bash
python -m venv .venv
```

```bash
.venv/Scripts/python -m pip install -r requirements.txt
```

```bash
.venv/Scripts/python -m uvicorn app.main:app --port 8605
```

Содан кейін `http://localhost:8605` ашыңыз. API құжаты `/docs` бетінде.

### ЖИ кілтін қосу

Кілтсіз жүйе шектеулі режимде жұмыс істейді: DOI, сұрақ, қарапайым мәтін, PDF құрылымы. Фото мен күрделі PDF оқу үшін серверді іске қосар алдында кілтті орта айнымалысына қойыңыз, оны кодқа жазбаңыз:

```bash
export ANTHROPIC_API_KEY=...
```

Әдепкі модель `claude-opus-5-5`, оны `SCIAGENT_MODEL` арқылы ауыстыруға болады. Қауіпсіздік сүзгісі сұранысты қабылдамаса, сервер жағындағы `fallbacks: "default"` басқа модельге ауыстырады.

### Интернетке шығару

`render.yaml` мен `Dockerfile` дайын. Render бетінде **New → Blueprint** арқылы осы репозиторийді таңдап, екі мәнді енгізіңіз:

- `SCIAGENT_DEMO_PASSWORD`: кіру құпия сөзі. Браузер сұрағанда пайдаланушы аты кез келген бола береді.
- `ANTHROPIC_API_KEY`: Claude API кілті. Бос қалса, чат шектеулі режимде жұмыс істейді.

Тегін жоспарда сервис 15 минут сұраныссыз тұрса тоқтайды, келесі ашылуы шамамен бір минут алады, ал енгізілген деректер өшіп, демо бастапқы күйіне қайтады. Деректі сақтау үшін ақылы жоспар мен тұрақты диск керек, `SCIAGENT_DB` пен `SCIAGENT_UPLOADS` сол дискке көрсетіледі.

Басқа контейнер хостингінде порт `PORT` айнымалысынан оқылады, әдепкісі `8605`. Тексеру беті `/healthz` құпия сөзсіз жауап береді, ал қалған беттердің бәрі құпия сөзбен жабық.

## Тесттер

```bash
.venv/Scripts/python -m pip install pytest httpx
```

```bash
.venv/Scripts/python -m pytest tests -q
```

Тесттер бағыттауды, тексеруді, рөлдерді, есеп құрылымын және агент жолын сынақ сервермен тексереді. Нақты модельмен тексеру үшін кілт керек.

## Қорғаудағы сценарий (5 минут)

1. **Докторант:** чатқа `1_makala_zhana.pdf` (ойдан жасалған үлгі) жібереді, агент бөлімді анықтайды, авторды сәйкестендіреді, «Подтвердить» басады.
2. **Докторант:** `2_makala_bazada_bar.pdf` (жарияланған нақты мақала) жібереді. Жүйе DOI-ді Crossref-тен тексеріп, мақаланың базада бар екенін табады.
3. **Жауапты:** «Очередь проверки», бәрін біріктіреді. ППС жарияланымы 56-дан 49-ға түседі. Чаттан «Что мешает сдать отчёт?» деп сұрайды.
4. **Кафедра меңгерушісі:** «Аналитика» диаграммалары, ғылыми жетекшілік, есепті келісу.
5. **Директор:** 6 кафедраны диаграммамен салыстырады, есепке қол қояды.
6. **Excel:** «Отчёт НИР» ресми нысан пішімінде ашылады.

Лауазым жоғарғы оң жақтағы мәзірдегі «Поменять позицию» арқылы ауысады.
